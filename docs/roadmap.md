# Дорожная карта OpenCode jobs

Дата актуализации: 2026-10-07.

Статус: согласованное направление развития после 0.3.0 preview. Этапы ниже
запланированы; они не описывают возможности установленной версии. Номера будущих
выпусков и календарные сроки определяются после проверки технических зависимостей.

## 1. Цель и исходное состояние

Пользователь может оставить несколько задач работать и вернуться к одному списку:
где требуется решение, что завершилось и где возникла проблема.

Главная отличительная возможность: режим **«Нужен я»**. Он собирает задачи,
ожидающие участия человека, сохраняет связь с исходным запросом и позволяет
перейти к нему с достаточным контекстом. Контексты проектов остаются разделёнными.

В 0.3.0 preview уже доступны фоновые задания, мониторинг вывода, расписания,
повторяющиеся задания, история текущей сессии, просмотр вывода и прямая остановка
через `/joblist`. Действующие возможности и ограничения описаны в
[руководстве по эксплуатации](operation.md) и
[руководстве по установке](../DEPLOYMENT.md).

## 2. Основные этапы

### 2.1. Проверка границ интеграции с OpenCode

**Результат:** подтверждённый состав первой версии «Нужен я».

На проверяемой версии OpenCode установить:

- Доступны ли плагину обычные фоновые команды, субагенты, запросы разрешений и
  вопросы пользователю.
- Можно ли надёжно связать событие с проектом, сессией и задачей.
- Можно ли открыть штатный запрос и узнать, что пользователь уже ответил.
- Как ведут себя встроенные уведомления при открытом, свёрнутом и закрытом
  терминальном клиенте.

**Критерий готовности:** каждый предполагаемый источник событий проверен небольшим
воспроизводимым сценарием. Возможности, требующие изменения самого OpenCode,
обозначены отдельно. Из результатов следует граница первой реализации.

**Зависимость:** первый этап определяет допустимый объём центра внимания и общего
списка. Наличие возможности в актуальной документации не подтверждает её наличие
в поддерживаемой версии хоста.

### 2.2. Доступность результата после завершения задачи

**Результат:** к выполненной работе можно вернуться позже.

- Сохраняемый вывод с ограничениями размера и срока хранения.
- Просмотр сохранённого вывода после удаления shell хостом.
- Понятный итог: результат, код завершения, причина остановки и время выполнения.
- Явное обозначение обрезанного или недоступного вывода.
- Системные уведомления через существующий механизм OpenCode с устранением дублей.

**Критерий готовности:** задача завершается при закрытом окне просмотра; после
повторного открытия доступны сохранённый результат и причина завершения. В
поддерживаемом режиме пользователь получает одно уведомление о соответствующем
событии. Поддерживаемые режимы определены проверками этапа 2.1.

**Решение до реализации:** выбрать срок хранения и объём сохраняемого вывода с
учётом возможного наличия чувствительных данных.

### 2.3. Первая версия «Нужен я»

**Результат:** ожидающие участия задачи не теряются среди сообщений.

- Отдельный список «Требуется действие».
- Проект, сессия, источник запроса и причина ожидания в каждой записи.
- Переход к штатному вопросу или разрешению.
- Отдельное представление завершённых результатов и ошибок.
- Согласование состояния между открытыми клиентами и восстановление после
  перезапуска.

**Критерии готовности:**

- Ответ в исходной сессии снимает ожидание в центре внимания.
- Простое открытие карточки не считается ответом.
- Повторная доставка события не создаёт второй пункт.
- Устаревший запрос нельзя выполнить повторно.
- Просмотр списка не вызывает модель.

Первая версия использует события, которые система может достоверно определить.
Обычная ошибка сама по себе не означает, что требуется решение человека.
Автоматическое определение решений по произвольному тексту не входит в первую
версию. Конкретные доступные источники определяются на этапе 2.1.

### 2.4. Общий обзор фоновой работы и проектов

**Результат:** один обзор работы на текущей машине.

- Задания плагина, доступные штатные фоновые команды и субагенты.
- Переключение между текущей сессией, проектом и общим обзором.
- Фильтры: требуется действие, выполняется, завершено, ошибка.
- Прямой переход к источнику и доступные штатные действия.
- Видимое указание возможностей: например, задача доступна для просмотра, но её
  остановка этим интерфейсом не поддерживается.

**Критерий готовности:** при работе в нескольких проектах пользователь находит
все поддерживаемые ожидания в одном месте. Ответы и действия направляются строго
в соответствующую сессию; контексты проектов не смешиваются.

**Зависимость:** состав исполнителей зависит от этапа 2.1. Минимальный центр
внимания может быть выпущен до полного объединения исполнителей.

### 2.5. Проверка ценности в повседневной работе

**Результат:** подтверждение, что «Нужен я» уменьшает ручной контроль.

При использовании в нескольких проектах проверить:

- Приходится ли обходить сессии в поисках ожидающих вопросов.
- Какие уведомления оказываются лишними.
- Хватает ли контекста карточки для принятия решения.
- Какие ожидания система пропускает.

По наблюдениям добавлять необходимые улучшения: группировку повторов, отложенное
напоминание или более содержательное описание запроса. Эти возможности остаются
кандидатами до подтверждения соответствующей потребности.

**Критерий готовности:** типовые сценарии проходят без ручного поиска ожидающих
вопросов; обнаруженные пропуски и дубли устранены. Результат подтверждён конкретными
сценариями использования.

## 3. Установка и сопровождение

Направление может развиваться независимо от центра внимания.

| Направление | Планируемый результат | Критерий готовности |
|---|---|---|
| macOS | Завершить согласованную поддержку: пользовательский LaunchAgent без администратора, работа до выхода из учётной записи | Установка, запуск, восстановление и остановка проверены на macOS; установщик отказывается перезаписывать существующую установку. Закрытие терминала не останавливает планировщик при работающем сервере. Проверки автоматического запуска после входа и перезагрузки обозначены отдельно |
| Обновление | Одно-подтверждённое автоматическое обновление: `scripts/update.js` проверяет релиз и SHA256, блокирует обновление при активных заданиях, сохраняет прежний runtime, заменяет только каталог плагина и автоматически откатывается при провале проверок; локальная команда `/jobs-update`. Ручной протокол остаётся для установок старше поддерживаемой | Сценарии «обновление» и «откат» воспроизведены изолированно на обеих ОС в CI и на реальной установке; задания сохранены; откат не требует восстановления всей БД; инструмент модели исключён |
| Диагностика | Версия, состояние сервера и планировщика, причина неисправности, следующее действие | Для воспроизведённых неисправностей диагностика показывает подтверждённую причину либо явно обозначает неопределённость и необходимую проверку |
| Жизненный цикл | Проверки сна и пробуждения, разрыва связи, перезапуска и выхода из системы | Для каждой заявленной платформы записаны проверенные сценарии и ограничения; неизвестное исполнение не запускается повторно автоматически |
| Совместимость | Матрица поддерживаемых версий OpenCode | Каждая заявленная версия подтверждена фактическими проверками |

## 4. Последовательность и ближайший шаг

Основная последовательность:

1. Проверка интеграции.
2. Сохраняемые результаты и уведомления.
3. Первая версия «Нужен я».
4. Общий обзор проектов.
5. Проверка на реальной работе и уточнение по наблюдениям.

Перевод уже выполняющейся команды в фон остаётся отдельным кандидатом после
проверки возможностей хоста.

Ближайший шаг: проверить источники событий и штатные действия для «Нужен я» по
этапу 2.1. После этого определить состав следующего выпуска и оценить работу.
Календарные сроки и номера будущих версий пока не назначены.
